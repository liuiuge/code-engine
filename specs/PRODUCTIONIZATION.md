## 0. 用户痛点的根因（已在代码中核实）

| 现象 | 根因（代码位置） | 说明 |
|------|------------------|------|
| 等得心慌、没事做 | `web/routes/problems.py:328` `asyncio.to_thread(_do_generate)` | 一次阻塞调用，返回**完整** `GenerateResult`，前端只能干等 |
| 看不到进度 | `infrastructure/logger.py` 的 `trace_node` 只在服务端记日志 | 节点级「进入/耗时」事件未推给前端 |
| 代码「一次性蹦出来」 | `infrastructure/config.py:190` `_invoke_with_timeout` 用 `model.invoke` | ChatOllama 原生支持 `.stream`，但被**刻意关掉**（注释：流式会让 httpx 读超时失效） |
| 想停停不了 | 无 cancel 机制 | local 慢模型曾跑 ~13 分钟（README 自述），只能干等 |
| 不知用了哪个模型 | 模型路由仅进服务端日志 | `[Model Route] ... -> minimax` 未暴露给前端 |

**核心判断**：痛点不在「功能缺失」，而在「过程不可见、不可中断、不可预期」。生产化第一刀必须切在这里（对应 PHASE1_PLAN 的 W0+W1：事件总线 / 流式 / SSE / 取消 / 前端面板）。

## 1. 与用户痛点的直接映射

| 用户原话 | 根因 | 生产化改法（详见 PHASE1_PLAN） |
|----------|------|-----------|
| 「时间长」 | 生成节点 invoke 全量返回 + 可能 local 慢模型 + thinking | 流式输出 + 进度条 + 默认更快模型/可切换 + 取消按钮 |
| 「没事做」 | 同步阻塞、无进度事件 | SSE 阶段事件 + 打字机代码 + 计时器 + 中止键 |

最小可行生产化（收益最大）：**SSE 进度事件 + 生成节点改流式 + 前端实时进度/中止面板** —— 均见 PHASE1_PLAN 的 P1-3 / P1-2 / P1-5。
